# SEO-аудит сайту «Тепло поруч»

**Дата:** 5 листопада 2026 року  
**Проєкт:** HeatingPumpSait  
**Production-домен:** `https://teplo-tvd.live`  
**Хостинг за наданими даними:** Hetzner Cloud  
**Мова та регіон:** українська; Вінниця та Вінницька область

## Підсумок

Production-сайт не вдалося перевірити з цього середовища: DNS-запити для `teplo-tvd.live` і `www.teplo-tvd.live` завершувалися `Could not resolve host` (curl, код HTTP `000`), а інструмент веб-перегляду також не відкрив домен. Тому доступність файлів, фактичні HTTP-редиректи, canonical у production та HTML, який отримує Googlebot, мають статус **не перевірено**.

Перевірка локального коду виявила, що поточна збірка орієнтована на базовий шлях `/HeatingPumpSite/`, тоді як для наданого production-домену очікується сайт у корені. У вихідному HTML немає canonical і robots-метатега; `public/robots.txt` та `public/sitemap.xml` відсутні. Статті рендеряться React у браузері, без локального prerender/SSR, тож початкова HTML-відповідь не містить їхнього тексту. Це проблеми або ризики локальної конфігурації; вони самі по собі не доводять, що production розгорнуто з цим самим кодом.

## Production-перевірки

| Перевірка | Результат | Примітка |
|---|---|---|
| `https://teplo-tvd.live/robots.txt` | Не перевірено | DNS не розв’язав домен; HTTP-відповідь недоступна. |
| `https://teplo-tvd.live/sitemap.xml` | Не перевірено | DNS не розв’язав домен; HTTP-відповідь недоступна. |
| Canonical на головній і статтях | Не перевірено | Production HTML отримати не вдалося. У локальному `index.html` canonical відсутній. |
| HTTP → HTTPS | Не перевірено | Запити до HTTP-хоста не дійшли до сервера через DNS. |
| `www` → `teplo-tvd.live` | Не перевірено | Запити до обох варіантів `www` не дійшли до сервера через DNS. |
| HTML статей для Googlebot | Не перевірено в production | Локальна реалізація віддає SPA-shell; див. локальні результати нижче. |
| Абсолютні URL у production-метаданих | Не перевірено | Production-метадані недоступні для огляду. |
| Наявність випадкового `noindex` у production | Не перевірено | HTTP-заголовки та production HTML недоступні. |

## Локальний код і конфігурація

### Robots і sitemap

- У `public/` є зображення, але немає `robots.txt` або `sitemap.xml`; у корені репозиторію також немає відповідних файлів.
- Поточна збірка не генерує карту сайту. На production ці URL можуть повертати 404, якщо їх не додає окремий шар хостингу.
- У зв’язку з недоступністю production фактичний статус-код для обох URL невідомий.

### Canonical та домен

- У `index.html` є `title`, `description` та кілька Open Graph метатегів, але немає `rel="canonical"`, `og:url` чи `meta name="robots"`.
- Отже, локальний код не задає canonical із `https://teplo-tvd.live` ні для головної, ні для статей.
- У початкових параметрах аудиту й у локальних метаданих були різні назви сайту. Актуальну назву «Тепло поруч» застосовано до метаданих та видимих підписів.
- Пошук у вихідних файлах не виявив localhost, тестового або неправильного абсолютного домену в SEO-метаданих. Знайдені абсолютні посилання ведуть на зовнішні джерела/виробників; локальний canonical і metadata URL не задані. Згадки localhost у Vite proxy, прикладах середовища та документації належать розробницькій конфігурації, не метаданим.

### HTTP, HTTPS, www та базовий шлях

- `vite.config.ts` задає `base: "/HeatingPumpSite/"`.
- `deploy/Caddyfile` перенаправляє лише `/` на `/HeatingPumpSite/` зі статусом 308, а файли обслуговує під цим префіксом. Це не відповідає звичному кореневому URL `https://teplo-tvd.live/` і може призвести до дублювання або неочікуваної структури URL. Чи так налаштовано фактичний production, не підтверджено.
- Caddy може автоматично налаштовувати HTTPS для доменного `SITE_ADDRESS`, однак реальні HTTP → HTTPS редирект, сертифікат і відповідність `SITE_ADDRESS` не перевірено.
- У локальному `Caddyfile` немає правила, яке явно перенаправляє `www.teplo-tvd.live` на основний домен. Редирект може бути заданий поза цим файлом; production-поведінка невідома.

### HTML статей для Googlebot

- `index.html` містить порожній `<div id="root"></div>` і завантажує клієнтський `src/main.tsx`; у ньому немає контенту сторінки статті.
- `src/App.tsx` вибирає статтю після запуску JavaScript на основі `window.location.pathname`.
- Для «Радіатори чи тепла підлога?» заголовок і опис встановлюються у `useEffect`, тобто після завантаження та виконання JavaScript. Інші перевірені компоненти статей не мають серверного формування метаданих.
- Локальна конфігурація не містить SSR або prerender. Тому початковий HTML, який повертає SPA fallback, не містить тексту статей, їхніх індивідуальних title/description чи canonical. Google може виконати JavaScript під час окремого етапу рендерингу, але це не замінює перевірку реального HTML та індексації production.

### Індексація та закриті сторінки

- У `index.html`, `src/` і `public/` не знайдено `noindex`, `nofollow` або robots-конфігурації, що закриває сторінки.
- Вихідний HTML не задає `noindex`, отже за замовчуванням сторінки не просять пошуковик вилучити їх з індексу. Водночас production-заголовки `X-Robots-Tag` і фактичні відповіді не перевірено.
- Відсутність `noindex` не гарантує індексацію: на неї також впливають доступність URL, robots.txt, canonical, відповідь сервера та якість HTML.

## Межі перевірки

Оглянуто локальні `index.html`, `src/App.tsx`, компоненти SEO-метаданих статей, `vite.config.ts`, `deploy/Caddyfile` і вміст `public/`. Виконано DNS/HTTP-запити до HTTP та HTTPS для apex і `www`, а також до `robots.txt` і `sitemap.xml`; усі запити зупинилися на помилці DNS до отримання HTTP-відповіді. Production HTML, статус-коди, заголовки, редиректи та поведінку Googlebot підтвердити не вдалося.

## Рекомендовані наступні кроки після погодження

1. Після виправлення звірити назву «Тепло поруч» у production HTML та Open Graph.
2. Звірити production DNS для apex і `www`, а після відновлення доступу перевірити відповіді всіх URL та ланцюжки редиректів.
3. Узгодити production URL-структуру: корінь домену чи `/HeatingPumpSite/`; локальні Vite/Caddy налаштування зараз задають префікс.
4. Після погодження змін підготувати canonical із `https://teplo-tvd.live`, `robots.txt`, sitemap із канонічними URL та окремі метадані для індексованих сторінок.
5. Вирішити, чи потрібен prerender/SSR для статей; потім перевірити початковий HTML production URL та відрендерений Googlebot HTML окремо.
6. Окремо визначити правила індексації службових сторінок, зокрема `/admin`, і підтвердити їх через robots/meta/header після деплою.
