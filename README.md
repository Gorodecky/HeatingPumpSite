# Тепло поруч

Фронтенд React/Vite знаходиться в корені репозиторію. API та схема PostgreSQL розташовані окремо в `server/`.

## Локальний запуск

Потрібні Node.js 20+ і PostgreSQL 14+.

1. Запустіть локальний PostgreSQL і створіть базу `heatingpump` (наприклад, `createdb heatingpump`).
2. Створіть конфігурацію сервера: `cp server/.env.example server/.env`. Вкажіть у `DATABASE_URL` коректне ім’я користувача, пароль і адресу PostgreSQL. Створіть `SESSION_SECRET` командою `openssl rand -base64 48`. Для локального запуску залиште `APP_ORIGIN=http://localhost:5173`. Файл `server/.env` ігнорується Git.
3. Встановіть залежності: `npm install` у корені та `npm install --prefix server`.
4. Застосуйте міграцію та згенеруйте Prisma Client: `npm run db:migrate`, потім `npm --prefix server run build`.
5. У першому терміналі запустіть API: `npm run dev:server`.
6. В іншому терміналі запустіть фронтенд: `npm run dev`. Vite проксуватиме `/api` до `http://localhost:3001`.
7. Створіть адміністратора командою `npm run admin:create`. Команда інтерактивно запитує логін і пароль (пароль не відображається) та зберігає лише хеш Argon2id.
8. Відкрийте `/admin` на локальному сайті для входу й перегляду останніх 100 заявок.

Серверний `npm run db:migrate` виконує `prisma migrate deploy`; для локальної розробки, коли потрібне створення нової міграції, доступна команда `npm --prefix server run db:migrate:dev`.

## API

- `POST /api/v1/leads` — публічне створення заявки. Потрібні `source` (`selection` або `contact`), ім’я, телефон і `consent: true`; для попереднього підбору обов’язкові населений пункт, площа, тип об’єкта, система опалення та термін реалізації. Дозволені поля суворо обмежені схемою. Сервер нормалізує рядки й телефон, записує згоду, серверний час та `POLICY_VERSION`. Відповідь містить лише UUID, дату створення і статус.
- `GET /api/v1/auth/csrf` — створення CSRF-токена й анонімної сесії.
- `POST /api/v1/auth/login`, `GET /api/v1/auth/me`, `POST /api/v1/auth/logout` — сесійна автентифікація адміністратора. Сесії зберігаються в PostgreSQL.
- `GET /api/v1/admin/leads` — список заявок лише для автентифікованого адміністратора із CSRF-токеном. Публічного читання заявок немає.

API обмежує частоту створення заявок і спроб входу. Сесійна cookie має `HttpOnly` і `SameSite=Strict`; у production також встановлюється `Secure`. Таблиця сесій створюється міграцією. Перед production задайте у `server/.env` сильний випадковий `SESSION_SECRET`, `APP_ORIGIN` з точним HTTPS origin сайту, `NODE_ENV=production` та `POLICY_VERSION`. Розмістіть фронтенд і API за одним origin через reverse proxy, який передає HTTPS і коректно налаштований `X-Forwarded-Proto`. Не відкривайте PostgreSQL назовні.

## Політика конфіденційності та готовність до запуску

Сторінка `/privacy` навмисно позначена як незаповнена заглушка. До публічного запуску власник сайту має надати й затвердити юридичне ім’я/назву, контактні дані, правову підставу та мету обробки, строки зберігання, порядок реалізації прав користувачів, відомості про одержувачів даних і хостинг. Не вигадуйте ці відомості. Узгодьте фактичний текст політики з реалізацією та оновіть `POLICY_VERSION` після кожної зміни політики.

Публічні форми зберігають ім’я, телефон та надані відповіді в PostgreSQL. Згода не приймає довільного тексту: сервер зберігає лише булевий факт, час сервера й версію політики. Не додавати рекламну згоду.
